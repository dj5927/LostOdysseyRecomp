# 0.6.0 prerelease audit repairs

Baseline: `9a1617af1b05dae5ea3d317f6479b8d3c467e4d0` (`v0.5.20`).
Branch: `0.6.0-prerelease`. No change to `main`, release tag, or published assets.

## Resolution map

| Audited defect | Implementation | Regression coverage |
| --- | --- | --- |
| WaitAll returned success after individual timeouts/partial consumption | Lock participating targets in address order, inspect the complete condition before consuming any state, one steady deadline and notified multi-wait domain | Event/semaphore/mutant mixes, partial readiness, timeout, duplicate targets, competing waiters and unrelated notification storm |
| Duplicate handles outlived their object or destroyed it twice | Independent handle tokens retain shared objects; operations acquire their own references; explicit object references retained separately | Alias close order, concurrent acquire/close, object references, close-source duplication |
| Closing thread handle joined worker | Worker owns shared control and completion event; closing handle detaches without invalidating worker state | Actual thread launcher/destructor extracted; blocked fake guest body, last-handle close, suspension and multiple completion waiters |
| Temporary shader failure poisoned cache | Bounded retry state, exception-safe attempt guard, transient compiler/module failures distinguished from deterministic negative results | Actual GetShader/prebuild extracted with null/throw/DXC fault injection and backoff assertions |
| Presentation allocation/map failure left inconsistent resources or Pending | Stage replacement resources before committing sizes/identities; display completion guard; no acquire/command begin before allocation/map succeeds | Actual presentation body with allocation/map/acquire faults, failed resize retaining old resources and minimized retry |
| Sampled vertex cache comparison missed writes | Exact CPU byte snapshot comparison with bounded cache byte budget; no GPU readback or cryptographic per-draw hashing | Every byte of a 16 KiB buffer including offset 600, eviction and oversized buffers |
| Window/backend flag data race | Atomic backend publication plus window-policy reapply request | Production compilation; actual display boundary fixture (GPU/OS calls faked) |
| Skip preparation failed to cancel some phases | Cancellation checkpoints in bundle load, source scan, variant enumeration, shader queue and PSO warm-up; incomplete aggregate not published | Actual prebuild cancellation at cached load and scan; bounded queue cancellation |
| Worker override bypassed serial/zero-core/platform memory policy | Serial takes priority; nonempty queue always gets an executor; separate pipeline override; physical memory query on Linux/macOS/Windows | Serial/max/zero-core parsing, launch failure and cancellation |
| Structurally valid shader package could be runtime-incompatible | Runtime and CLI share the same contract/prelude; verify-runtime checks expected image/contract before package staging; immutable release shader-input ref | Real pack writer/reader/CLI, wrong contract/image, short/missing image, explicit override, same-path staging and absent optional package |
| CI did not protect main or require new pack tests | main/menu/prerelease pushes and PRs; portable core/integration/release tests on both OSes; reusable native audit gates release jobs | Native audit workflow and reusable release dependency |
| x86 compiler flag passed to ARM | Gate Sandy Bridge architecture option on the target processor | Actual CMake architecture option extracted and evaluated for x86_64, AMD64, aarch64 and arm64; not a complete ARM port |

## Reproduction

Run from a checkout with submodules initialized. Linux also needs the Plume X11 platform headers (`libx11-dev` on Ubuntu).

```sh
python3 tools/tests/native_audit.py --cxx clang++ --sanitize --out out/audit/native
python3 tools/tests/menu_boundary_regression.py --cxx clang++ --sanitize --out out/audit/menu
python3 tools/tests/shader_prebuild_regression.py --cxx clang++ --sanitize --out out/audit/prebuild
python3 tools/tests/kernel_lifetime_regression.py --cxx clang++ --sanitize --out out/audit/lifetime
python3 tools/tests/presentation_failure_regression.py --cxx clang++ --sanitize --out out/audit/presentation
cmake -S tools/shader_pack -B out/audit/pack -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build out/audit/pack --target LoShaderPackTool LoPortableShaderPackTest LoPortableShaderPackIntegrationTest LoPortableShaderContractTest
ctest --test-dir out/audit/pack --output-on-failure
```

The added prerelease header suite passed 16,435 checks locally with Clang ASan/UBSan and on the Linux runner with GCC. Actual extracted thread, presentation, prebuild and menu routines passed their local fault-injection regressions. Portable pack core/integration/release-contract CTest passed locally (3/3). The first complete Windows CPU workflow passed, including pack CTest (3/3). The first Linux native pass exposed two test-environment issues: missing `X11/Xlib.h` on the bare runner and a legacy `ConsentEpoch` fixture definition missing the production `noexcept` specification. Both were corrected without skipping the fixture. Windows and Linux production translation-unit compilation of the eight changed runtime `.cpp` files and the CMake vertex-cache target passed. This built the actual runtime files against generated PPC headers and real dependency checkouts, rather than the extracted-test stubs. Subsequent Windows/Linux results are recorded in GitHub Actions, not inferred from local tests.

## Validation limits

CPU fixtures and extracted routines are not full-game execution. Extracted presentation/shader tests explicitly fake device, DXC, OS and game I/O boundaries; real production translation-unit compilation is separate. No full runtime link, real GPU recovery, complete playthrough, ARM runtime, or Steam Deck 15 W / 720p60 certification is asserted here.

Exact vertex comparison trades additional CPU memory reads/storage for correctness. Its effect on frame time requires measurement. Real occlusion queries and additional Steam Deck performance work remain separate tasks; this patch does not claim to implement them.
